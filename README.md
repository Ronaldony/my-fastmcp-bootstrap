# FastMCP Bootstrap

**기존 서비스의 MCP를 연결하고, 필요한 도구를 선별해 노출하며, 실제 서비스 호출까지 빠르게 검증하기 위한 범용 FastMCP 기능 설계도입니다.**

목표는 **최소한의 구축 시간과 금전적 비용으로, 목적에 맞는 MCP Gateway를 구성하는 것**입니다. 특정 프로젝트의 구현을 복제하기보다 FastMCP의 기본 기능과 검증 순서를 재사용합니다.

> **핵심 원칙:** 프레임워크가 제공하는 기능을 먼저 조합하고, 용도별 차이는 연결 정보와 정책으로 표현합니다. 추가 코드는 기본 기능만으로 충족되지 않는 요구에 사용합니다.

**[전체 부트스트랩 설계도 읽기 →](./fastmcp-bootstrap-blueprint.md)**

## FastMCP 중심 연결 구성

```text
MCP 클라이언트
      ⇅
클라이언트가 지원하는 MCP 접속 방식
      ⇅
┌─────────────────────────────────────┐
│           FastMCP Gateway           │
│                                     │
│       도구 노출 · 검색 · 호출       │
│                  ⇅                  │
│        namespace · 라우팅          │
│                  ⇅                  │
│     MCP별 ProxyProvider / Client    │
└─────────────────────────────────────┘
           ⇅                   ⇅
         stdio          Streamable HTTP
           ⇅                   ⇅
      로컬 MCP 서버      별도로 실행 중인 MCP 서버
           ⇅                   ⇅
      서비스 또는 도구      서비스 또는 도구
```

**클라이언트 쪽 접속 방식과 연결 대상 MCP의 transport는 독립적으로 선택합니다.** Gateway를 HTTP로 제공하면서 일부 MCP에는 stdio로 연결할 수 있습니다.

Gateway는 연결한 MCP의 기능을 발견하고 중계합니다. 서비스 내부에 bridge가 필요하면 **Gateway → MCP 서버 → 서비스 내부 bridge → 서비스**로 연결합니다. 서비스 본체의 준비는 서비스 쪽 책임이며, stdio 연결에 필요한 MCP 자식 프로세스 생성은 transport의 일부입니다.

연결 형태와 책임 경계는 [설계도 §2](./fastmcp-bootstrap-blueprint.md#2-fastmcp-중심-연결-구성)를 참고합니다.

## 핵심 기능과 구성 규칙

| 필요한 기능 | FastMCP 구성 요소 | 결정할 내용 |
|---|---|---|
| MCP 연결·통합 | `ProxyProvider`, client, transport | 연결 대상, 실행 명령 또는 endpoint, 인증 방식 |
| 도구 자동 발견 | Provider의 discovery | 원본 도구의 이름·설명·입력 스키마 활용 |
| 이름 충돌 방지 | `Namespace` 또는 provider namespace | MCP별 고유 식별 범위 |
| 직접 노출 | 기본 tool listing | 초기 목록으로 제공할 도구 |
| 검색형 노출 | Tool Search transform, `always_visible` | 직접 노출 도구와 검색 후보의 구분 |
| 실제 호출 중계 | ProxyProvider의 호출 경로 | Gateway 도구 이름과 원본 MCP 도구의 연결 |
| 처리 기록 | Middleware, lifespan, 로거 | Gateway 처리와 실제 upstream 통신의 구분 |

여기서 **upstream**은 Gateway가 연결하는 서비스 MCP 서버를 뜻합니다.

**서버 등록과 도구 discovery는 다릅니다.** 연결할 MCP와 접속 정보는 구성자가 정하고, 해당 MCP의 상세 도구 정의는 discovery로 가져옵니다. 도구 스키마를 다시 작성하는 대신 원본 정의를 사용합니다.

**정책과 호출은 동일한 이름 체계를 사용합니다.** 여러 MCP를 통합할 때 namespace를 먼저 정하고, 직접 노출·제한 정책은 namespace 적용 이후의 도구 이름을 기준으로 구성합니다.

**인스턴스별 실행환경과 설정은 독립시킵니다.** 의존성을 재현 가능한 조합으로 고정하고 연결 정보와 로그 목적지를 구분합니다. 실행환경 분리는 서비스 접근 권한의 격리와 별개입니다.

상세 규칙은 [설계도 §3](./fastmcp-bootstrap-blueprint.md#3-핵심-기능과-조합-규칙)에 있습니다.

## 도구 노출 방식 선택

도구 정의의 양이 작고 직접 선택이 충분하면 **직접 노출형**을 사용합니다. 전체 스키마를 매번 제공하는 비용이 크면 **선별 노출형**으로 구성합니다.

선별 노출형의 초기 목록은 다음과 같습니다.

```text
자주 사용하는 Public 도구 + search_tools + call_tool
```

| 구분 | 초기 도구 목록 | 검색 결과 | 사용 방식 |
|---|---|---|---|
| **Public** | 원본 정의 포함 | 기본 검색에서는 중복 방지를 위해 제외 | 도구 이름으로 직접 호출 |
| **Searchable** | 원본 정의 숨김 | 질의와 결과 수 제한에 따라 제공 | 이름·입력 스키마를 확인한 뒤 `call_tool`로 호출 |
| **Restricted** | 제외 | 제외 | 명시적 제한 정책으로 호출 거부 |

`Public`은 초기 목록에 보인다는 의미이지 인증 없이 공개한다는 의미가 아닙니다. `Searchable`은 도구 선택 방식이며 보안 경계가 아닙니다. 이름을 아는 원본 도구의 직접 호출까지 막아야 한다면 `Visibility` 등으로 별도의 제한을 적용하고, 직접·간접 호출 모두에서 확인합니다.

검색 방식은 도구 설명의 용어와 관련도 순위가 유용하면 `BM25SearchTransform`, 이름이나 패턴 중심이면 `RegexSearchTransform`을 선택합니다. Public 후보는 반복 사용 빈도가 높고 다른 작업의 시작점이 되는 도구로 좁힙니다.

**선별 노출의 효율은 초기 목록 크기만으로 결정하지 않습니다.** 검색 한 번의 왕복과 반환되는 스키마 크기까지 포함해 직접 노출과 비교합니다. 노출 계약의 상세 내용은 [설계도 §4](./fastmcp-bootstrap-blueprint.md#4-도구-노출을-선별하는-방법)에 있습니다.

## 실제 호출 흐름

```text
직접 노출형
클라이언트 → 노출 도구 선택 → 스키마에 맞는 인자
→ Gateway 정책·라우팅 → 원본 MCP → 서비스 결과

검색 후 호출
클라이언트 → search_tools → 도구 이름·입력 스키마 확인
→ call_tool(name, arguments) → 같은 정책·라우팅 경로
→ 원본 MCP → 서비스 결과
```

검색 결과의 이름과 스키마를 그대로 사용합니다. `call_tool`은 새로운 실행 권한을 부여하는 기능이 아니라 공통 호출 진입점입니다.

성공 여부는 **연결 성공 → MCP 호출 완료 → 실제 서비스 작업 성공**으로 나누어 확인합니다. 도구 목록 조회나 정상 HTTP 응답만으로 서비스 작업까지 성공했다고 판정하지 않습니다.

## 가장 짧은 구축 순서

**첫 MCP 하나로 실제 호출을 통과시킨 뒤, 검증된 연결 패턴을 다른 MCP에 적용합니다.**

| 단계 | 수행할 일 | 통과 기준 |
|---|---|---|
| **1. 입력 확정** | 핵심 작업, 연결 대상, transport, 클라이언트, 인증 조건을 정합니다. | 접속 정보와 기대 결과가 정해집니다. |
| **2. 최소 연결** | 독립 실행환경에 FastMCP를 구성하고 MCP 하나를 연결합니다. | 원본 도구 정의를 discovery로 받습니다. |
| **3. 실제 호출** | 서비스에 의존하는 대표 도구를 원본 스키마로 실행합니다. | 서비스 수준의 기대 결과를 얻습니다. |
| **4. 통합·선별** | 필요한 MCP를 추가하고 namespace와 도구 노출 정책을 적용합니다. | 이름 충돌 없이 선택한 호출 경로가 동작합니다. |
| **5. 기록 확인** | Gateway·MCP 통신 기록을 실제 호출 결과와 대조합니다. | 대상 도구·결과·오류를 구분할 수 있습니다. |
| **6. 최종 클라이언트 검증** | 실제 사용할 클라이언트에서 대표 작업을 실행합니다. | 클라이언트부터 서비스까지 전체 경로가 확인됩니다. |

연결 실패는 연결 경계에서, 도구 실행 실패는 실제 MCP·서비스 응답에서 원인을 확인합니다. 여러 호출에 걸쳐 상태를 사용하는 MCP는 세션 유지 요구도 검증합니다.

## 로그와 선택 기능

기록은 **FastMCP 자체 처리**와 **FastMCP ↔ MCP 통신**의 두 범주로 구분합니다. 시각, 대상 MCP, 실제 도구 이름, 작업, 결과, 소요시간을 남기고 구간을 연결해야 하면 상관 식별자를 사용합니다.

기본 기록은 메타데이터 중심으로 구성합니다. 인자·응답 본문·인증정보를 그대로 남기지 않고, 예외에도 입력값이 포함될 수 있음을 고려합니다. 재시작 후에도 기록을 이어서 확인할 수 있게 하고 저장량에 상한을 둡니다.

**Gateway middleware 기록은 실제 upstream 송수신 기록과 같지 않습니다.** 캐시 응답, 내부 라우팅, 연결 시도, 실제 RPC를 구분해 기록 범위를 검증합니다.

| 추가 요구 | 선택할 기능 | 확인 기준 |
|---|---|---|
| 특정 도구 사용 제한 | `Visibility` 기반 제한 | 모든 호출 경로에서 제한 적용 |
| 외부 클라이언트 접속 | 인증된 연결 경로 | 클라이언트 호환성과 서비스 접근 범위 |
| 반복 discovery 비용 감소 | Provider 메타데이터 캐시 | 도구 정의 갱신 요구와 조회 비용의 균형 |
| 호출 구간별 원인 추적 | upstream RPC 연관 기록 | 원본 호출 동작 보존과 기록의 정확성 |

각 기능은 구체적인 필요와 통과 기준을 정한 뒤 추가합니다. 상세 기록 범위와 선택 기준은 [설계도 §6](./fastmcp-bootstrap-blueprint.md#6-로그와-선택-부가-기능)에 있습니다.

## 새 용도에 적용할 입력

아래 항목을 먼저 채우고 설계도의 구축 순서를 적용합니다. 도구별 스키마는 연결한 MCP에서 받습니다.

```text
핵심 작업과 기대 결과:
연결할 MCP의 역할:
MCP별 transport · 접속 정보 · 인증 방식 · namespace:
클라이언트 접속 방식:
도구 노출 방식과 Public 후보:
명시적인 도구 제한 요구:
기록 범위와 필요한 연관 추적:
최종 클라이언트에서 실행할 대표 검증 요청:
```

완료 기준은 **선택한 MCP를 연결하고, 정책에 맞게 도구를 노출하며, 최종 클라이언트의 대표 작업을 성공시키고, 필요한 로그로 그 호출을 설명할 수 있는 것**입니다.

비용은 초기 구현 시간뿐 아니라 **추가 코드·의존성의 유지 비용, 도구 선택·호출의 왕복, 연결 서비스의 이용 요금**까지 함께 평가합니다. 구성과 검증은 Git에 보존하고 자격정보·로그·일회성 산출물과 구분합니다.
